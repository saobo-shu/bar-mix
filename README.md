# 调酒台 · 风味配比实验室

一个单页的调酒工具。挑材料倒进杯子，实时看风味雷达图、一个 0–100 的分数，和"下一步该加什么"的建议。

不用登录、不用装东西——整个网站就是一个 HTML 文件，断网也能用。

访问量用百度统计看（多少人来了、从哪来、什么设备）。你调了什么酒、放了哪些材料都不会被记录、也不会被上传，那些只在你自己的浏览器里算。统计脚本只在网址打开时加载，本地双击的那个文件不上报，断网时它加载失败、页面照常跑。

线上版：https://saobo-shu.github.io/bar-mix/

## 怎么打开

自己看，双击 `dist/调酒台.html`。发给别人也是发这一个文件，微信、QQ、邮件都行，对方在电脑上双击就能用。

手机上：打开上面那个网址，再「添加到主屏幕」。桌面会多一个杯子图标，点开是全屏、没有地址栏，断网也能用。

## 里面有什么

178 种材料，其中 54 瓶基酒，六大基酒各占一个分类标签。44 个经典配方按家族分成四组：高球·长饮 16、酸类 15、烈酒向 11、热饮 2。杯子有 7 种，从便利店冰杯到马天尼杯。

每样材料都标了三件事：在哪买（便利店 / 超市 / 网购）、建议温度（冷冻 / 冷藏 / 常温），和没冰箱能放多久（放心买 / 注意 / 高风险）。最后一栏是专门为没有冰箱的住处做的——味美思、淡奶油这些开瓶就必须冷藏的，会被标成高风险，并提醒你别买大瓶。

## 冰化出来的水，是按温度算的

杯子里的冰化掉多少，取决于倒进去的材料有凉。所以每样材料都带一个温度：冷冻 -18℃、冷藏 5℃、常温 25℃。默认值按常理给（烈酒、糖浆常温，气泡饮料和果汁按"便利店买来就是冷的"算），点一下材料上的温度标签就能改。

算的是初中物理的热量平衡：材料降温到 0℃ 放出的热，先扣掉把冰从 -18℃ 捂到 0℃ 的那笔过路费，剩下的才化冰。同样一杯金汤力，冷冻基酒加冷藏汤力水一滴冰都不用化，全部常温则会化掉 40ml 水、把酒精度从 10.9% 拉到 9.1%。这就是"基酒放冷冻、饮料买冷藏"最实际的价值。

做法（兑和 Build / 搅拌 Stir / 摇和 Shake）也在这里：兑和的酒，水全来自冰化；摇和和搅拌的酒在摇壶里就已经和冰换过热量，滤出来接近 0℃，所以按经验的 25% / 20% 算，不再叠加杯里化冰那笔。

「① 杯子里」还有一条带子，把最后这杯酒拆开：倒进去的酒液、摇和/搅拌在摇壶里加的水、杯里的冰化出来的水，三笔加起来正好是上面的「总液量」。冰被室温慢慢化开的那部分写在带子后面（十几分钟的量），不算在里面。

## 分数怎么看

四个分项加权：平衡、复杂度、结构、浓度。平衡的权重永远最大——不管选哪套方案，好喝都是第一位的。

权重本身可以选，一共五套：均衡、只看味道、香气优先、做法优先、度数优先。旁边还有「口味」（清淡 / 标准 / 浓烈）和「冰量」（满冰 / 半杯冰 / 不加冰）。口味只管浓度这一项，所以换方案时它的影响力会跟着变——选「度数优先」时它最要紧，选「只看味道」时几乎不影响。

杯子里只有一样酒、没有任何配料时（比如纯饮一杯麦卡伦），不评分，只给一段味道描述。没有配料的时候，"这杯好不好"不是这个工具能回答的。加一条柠檬皮或一点气泡水，它就切回评分模式。

## 文件

`data.js` 是全部内容所在——材料、风味数值、配方、杯子、保存档案都在里面。想加一种材料或改一条配方，只改这个文件就够了。

`dev.html` 是开发用的源文件，引用 `app.css` / `app.js` / `data.js`。`tools/build.js` 把它们打包成 `dist/` 里的单文件。`self-check.js` 和 `tools/audit.js` 是两个检查脚本：前者看有没有面板渲染不出来、数据对不对得上，后者把 44 配方 × 7 杯型 × 3 冰量 × 5 套评分方案全跑一遍，找自相矛盾的地方。部署和更新写在 `DEPLOY.md`。

## 数据来源

材料清单和配方的比例，参考了一份「鸡尾酒配方本」（191 条经典配方），提取出来的原始数据放在 `tools/reference-recipes.json`，可以当字典查。经典酒的结构是共通的——酸、糖、苦精搭骨架——具体比例各家略有出入。
